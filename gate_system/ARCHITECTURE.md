# Архитектура gate_system

Система автоматического открытия ворот по номеру РФ. Работает 24/7 на
Raspberry Pi 5, разрабатывается на macOS. Документ описывает фактическое
устройство кода.

---

## 1. Принципы

* **Чистая архитектура (порты и адаптеры).** Ядро (`gate/core`) знает только
  абстракции из `gate/core/interfaces.py`: камера, детектор, распознаватель, реле,
  хранилища, уведомления. Конкретные реализации подключаются в одном месте:
  `gate/app.py` (Composition Root).
* **Отказ периферии не роняет ядро.** Нет интернета: ворота открываются, Telegram
  догонит. Нет реле: система работает и громко сообщает. Модели распознавания не
  загрузились: повтор в фоне, камера не блокируется.
* **Одинаковый код на Маке и Pi.** Различие одно: `relay.enabled` в конфиге
  (тестовый режим или реальное GPIO).
* **Всё проверяется тестами без железа:** часы, сон, загрузчики моделей, GPIO,
  HTTP и отправка в Telegram инъектируются.

## 2. Пакеты

| Пакет | Ответственность | Ключевые модули |
|---|---|---|
| `gate/core` | домен и бизнес-логика, без внешних зависимостей | `models` (сущности), `interfaces` (порты), `pipeline` (цикл камеры, решение, анти-повтор), `aggregator` (сборка номера по кадрам), `motion` (движение номера), `coordinator` (въезд/выезд), `plates` (нормализация номера РФ) |
| `gate/vision` | компьютерное зрение | `camera` (RTSP + фоновый «свежий кадр»), `detector` (YOLO, рамка номера), `nomeroff_ocr` (Nomeroff-Net), `ocr` (создание распознавателя), `snapshot` (картинка для «📷 Фото») |
| `gate/hardware` | железо ворот | `relay` (GpioRelay через gpiozero+lgpio, DryRunRelay), `gate_controller` (импульс, защита от двойного импульса) |
| `gate/storage` | данные | `database` (SQLite WAL + атомарный JSON для конфига), `whitelist`, `admins`, `history` (+ фото) |
| `gate/bot` | интерфейс пользователя | `telegram_bot` (CommandRouter: права и команды; TelegramNotifier: уведомления и запуск бота), `menu` (кнопочное меню) |
| `gate/services` | фоновые службы | `diagnostics`, `watchdog`, `network`, `proxy` (proxy6) |
| `gate/common` | общее | `logger` (ротация, перехват исключений, маскировка токенов/паролей, тишина сторонних предупреждений), `events` (понятный журнал), `utils` |
| `gate` | сборка | `app` (Composition Root, GateApp), `config`, `paths` |

Зависимости направлены внутрь: `bot`, `vision`, `hardware`, `storage` и `services`
зависят от `core`, а `core` ни от кого. `app.py` знает всех.

## 3. Потоки во время работы

```
                ┌────────────────────── процесс python main.py ───────────────────────┐
 RTSP въезд ──► │ grab:въезд ──свежий кадр──► vision:въезд ─┐                         │
 RTSP выезд ──► │ grab:выезд ──свежий кадр──► vision:выезд ─┤  общий YoloDetector      │
                │                                            │  общий Nomeroff (замки)  │
                │                                            ▼                          │
                │                         AccessDecision ──► RelayGateController ──► GPIO17 ──► реле ──► Nice SbS
                │                               │  │
                │                 SQLite (WAL) ◄┘  └─► TelegramNotifier ──► telegram (свой asyncio-цикл)
                │                                                                       │
                │ diagnostics (раз в 60 с) · watchdog (heartbeat камер) · network · proxy │
                │ startup: фоновая загрузка Nomeroff                                     │
                └────────────────────────────────────────────────────────────────────────┘
```

* **grab:\<камера\>** (`LatestFrameSource`) непрерывно читает поток и хранит только
  последний кадр. Здесь же переподключение с задержкой 1 → 2 → 4 … 30 с.
* **vision:\<камера\>** (`RecognitionPipeline`) берёт свежий кадр, распознаёт и
  принимает решение. Пропущенные за время распознавания кадры засчитываются в
  прореживание (`frame_seq`), поэтому задержка не накапливается.
* Модели **общие** для камер и защищены замками: модели PyTorch и ultralytics не
  потокобезопасны, а две копии съели бы вдвое больше памяти.
* **watchdog**: если поток камеры не подаёт признаков жизни 120 с, процесс
  завершается, и systemd его перезапускает. Аппаратный watchdog Pi перезагружает
  саму ОС, если зависла она.

## 4. Камера: автомат состояний (адаптивный режим)

```
                  рамка номера (≥ plate_conf)
                  [выезд: и номер СДВИНУЛСЯ]
   ┌────────┐ ──────────────────────────────────► ┌──────────┐
   │ ПРОСТОЙ │                                      │ АКТИВНЫЙ │
   │ best.pt │ ◄────────────────────────────────── │ best.pt + │
   │ 1 раз/с │   active_hold_s без номера           │ Nomeroff  │
   └────────┘   [выезд: без движения]               │ каждый 3-й│
                                                    └──────────┘
```

* **Въезд:** будит любая рамка номера.
* **Выезд** (`require_motion`): будит только сдвиг рамки между проверками.
  Распознавание запускается, когда движение подтверждено (`motion_confirm_frames`).
  «Память движения» (`motion_memory_s`) позволяет дочитать номер машины, которая
  подъехала и встала у ворот. Машина, стоящая давно, камеру не будит.
* Пока кто-то заезжает, выезд приглушён на 60 с (`CameraCoordinator`).

## 5. От кадра до открытия

```
кадр ─► detect_plate (best.pt) ─► вырезка рамки +30% ─► Nomeroff ─► текст
     ─► PlateAggregator: голосование основной части (А123ВС) и региона (777)
        по свежим (≤30 с) кадрам; полный номер, прочитанный целиком, приоритетнее
     ─► номер собран ─► [выезд: движется? не приглушён?]
     ─► AccessDecision:
          в белом списке  → анти-повтор (окно) → импульс реле → фото → история → «✅ Ворота открыты»
          не в списке     → свой анти-повтор   → фото → история → «🚗 Неизвестный» + кнопки
```

Анти-повтор раздельный для своих и чужих: отказ чужому номеру не блокирует его
открытие, если владелец тут же добавил номер в белый список.

## 6. Хранилище

* `data/gate.db`, SQLite в режиме WAL с `synchronous=NORMAL`: база не портится при
  внезапном отключении питания, а SD-карта не переписывается целиком на каждое
  событие (как было с JSON).
* Таблицы: `whitelist(plate, note, added_at)`, `admins(user_id, note, added_at)`,
  `events(...)`, `meta` (служебные отметки).
* Номер хранится в каноническом виде (кириллица, без пробелов). Номер, набранный
  латиницей, совпадает с распознанным.
* История ограничена `history_max_records`, фото ограничены `photos_max_files`,
  логи ротируются.

## 7. Надёжность

| Риск | Механизм |
|---|---|
| Камера пропала | переподключение с задержкой; одно событие «камера не отвечает» на весь обрыв; статус по каждой камере |
| Поток завис | watchdog → выход процесса → systemd `Restart=always` (без лимита попыток) |
| Зависла ОС | аппаратный watchdog Pi (`RuntimeWatchdogSec=15`) |
| Долгая загрузка моделей | загрузка заранее в фоне; камера не блокируется; повтор при сбое раз в 5 мин |
| Двойной импульс останавливает ворота (SbS) | `relay.min_interval_s`; рекомендация включить «Кондоминиум» |
| Реле осталось замкнутым | `try/finally` в импульсе, `initial_value=False` при старте |
| Нет интернета | ядро работает; Telegram переподключается сам; прокси с автопокупкой |
| Отключение питания | SQLite WAL, атомарная запись JSON-конфига |
| Переполнение диска | ротация логов, лимиты фото и истории, лимит journald 100 МБ |
| Износ SD-карты | WAL; временные кадры Nomeroff в `/dev/shm` (оперативная память) |
| Двойной поток к одной модели | замки в детекторе и распознавателях |

## 8. Решения под Raspberry Pi 5

* **GPIO:** на Pi 5 GPIO обслуживает чип RP1, поэтому `RPi.GPIO` там не работает.
  Используется `gpiozero` + `lgpio` (`GPIOZERO_PIN_FACTORY=lgpio` в сервисе).
* **Python 3.12** ставится через `uv`: Nomeroff-Net не работает на 3.13, а в новой
  Pi OS по умолчанию 3.13.
* **PyTorch только CPU:** колесо с PyPI на Linux тянет CUDA-библиотеки (ГБ),
  поэтому torch ставится из `download.pytorch.org/whl/cpu`.
* **Свежий кадр в отдельном потоке:** на Pi распознавание медленнее потока камеры.
* **Адаптивный режим:** в простое работает только `best.pt` (~26 мс на Маке, сотни
  мс на Pi) раз в секунду; тяжёлый `yolov11x` Nomeroff включается, только когда
  номер в кадре.
* **Время:** события хранятся в UTC, показываются в местном часовом поясе;
  `install.sh` ставит Europe/Moscow, если на Pi стоит UTC.

## 9. Как расширять

* **Другое реле** (USB и т.п.): новый класс-реализация `Relay` в
  `gate/hardware/relay.py` и выбор в `build_relay()`. Ядро не меняется.
* **Ещё одна камера:** новый элемент в `cameras` конфига.
* **Другой распознаватель:** реализация `OcrEngine` с методами
  `warmup / is_ready / state` и создание в `build_ocr_engine()`.
* **Новая кнопка бота:** метод `cmd_*` в `CommandRouter` (права и текст) и
  обработка в `MenuController`. Обе части тестируются без Telegram.
